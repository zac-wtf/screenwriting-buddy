# 观看过程与反馈诊断

用于成稿审读、模糊反馈与改法比较。最终审核归人工。

## 沿初次观看者接收信息的顺序

| 检查点 | 问题 |
|---|---|
| 留下的理由 | 这里有什么值得关注的异常、处境、画面或关系？观众理解吗？ |
| 正在等待 | 观众期待什么结果或有什么具体疑问？期待是否持续？ |
| 获得的进展 | 增加了什么行动、信息、情感或局部满足？是否重复先前的作用？ |
| 本条兑现 | 结尾怎样回应期待？连续短剧是否既有进展，又自然打开后续问题？ |

不必逐段交付整张表，只报告最影响观看的几个位置及原因。缺少实测时，不编造流失秒数、完播概率或流量预测。

## 常见问题与可行方向

- 开场信息很多而期待不清：从体现设定用途的处境切入，在使用或受阻时补必要解释。
- 连续受挫而缺少进展：增加有分量的行动、发现或局部成功，让后续阻碍来自其后果。
- 反转多却没有积累：检查是否围绕同一事件，减少互不相关的秘密和灾难。
- 人物行为只为刺激：寻找更可信的利益、信息差或压力，避免突然失去判断力。
- 开场承诺与结尾错位：调整兑现方式或开场期待，优先保留已定方向。
- 结尾只是截断：让当前行动先产生实质结果，再以新处境推动下一集；无需每集解决全部矛盾。
- 解释替代情绪：让关系、行为和后果承担表达，删掉已被戏表现的总结。
- 很快却仍无聊：检查是否有值得等待的人与事，不能只缩句和加转场。

上述是诊断入口，不是预设结论。安静、缓慢、开放结尾本身不是错误。

## 收到“不好看”时

1. 回到当前有效稿和已定方向，定位片段，提出最可能原因与文本依据。
2. 区分问题与方案。用户提议增加反派可能是在解决阻碍弱；先理解目的，同时尊重明确的改写指令。
3. 若两种诊断需要不同改法，问一个关键问题并给推荐。例如“你更介意他一直受气，还是最后反击太容易？我倾向先修前者，因为中段重复三次相同受挫。”
4. 原因清楚后局部修改，必要时给短示例。只有结构性问题才扩大到全稿。
5. 回查必要信息、人物动机、伏笔和锁定方向，避免修一处破坏另一处。

## 判断边界与终检

使用“这里可能失去兴趣，因为两场都没改变处境”等有依据的判断，不宣称必然划走、必成爆款或已通过人工审核。

有真实反馈时，区分用户感受、受众反应和平台数据。多名观众在同一位置失去兴趣能提高诊断可信度，不能证明某个改法必然有效。用户要求版本比较时围绕同一个问题展示差异。

确认期待与兑现对应、主要段落持续提供进展、行动和规则连贯、修改符合已定方向。交付供人工审阅的稿件及必要说明，不以自评分或自检证书代替审核。
